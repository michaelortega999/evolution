- Phones (<768px, except /auth) render the hand-built Evolution OS prototype from public/evolution-mobile/ in a full-screen frame (MobileApp in __root); src/lib/mobile-bridge.ts syncs its tasks/events with desktop evoTasks/calendar via a three-way merge against a stored base snapshot (full sync before the frame loads, desktop-only writes while it runs). Why: keeps the mobile design pixel-exact without losing unsynced items or resurrecting deletes.
- Cloud sync in src/lib/evolution-data.ts never uploads before a successful read of the account, treats read errors as errors (not empty accounts), tags local data with its owner and backs up foreign data instead of uploading it. Why: prevents overwriting or leaking data across accounts.
- Calendar day keys use local time (localISO in src/lib/utils.ts; evoLocalKey in the phone prototype), never toISOString(). Why: UTC keys shift days for users outside UTC.
- Bridge rules are covered by src/lib/mobile-bridge.test.ts (bunx vitest run). Why: sync regressions are silent data loss.
