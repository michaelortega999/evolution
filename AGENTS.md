- Phones (<768px, except /auth) render the hand-built Evolution OS prototype from public/evolution-mobile/ in a full-screen frame (MobileApp in __root); src/lib/mobile-bridge.ts syncs its tasks/events with desktop evoTasks/calendar via a three-way merge against a stored base snapshot (full sync before the frame loads, desktop-only writes while it runs). Why: keeps the mobile design pixel-exact without losing unsynced items or resurrecting deletes.
- Cloud sync in src/lib/evolution-data.ts never uploads before a successful read, treats read errors as errors, archives the previous owner's local data before reading a new account, and merges local edits record-by-record (by id) onto the cloud copy using a per-account synced snapshot as base; uploads are single-flight (later edits coalesce, base advances only for the acknowledged payload, a session generation drops stale completions); failed saves leave changes dirty and retry; the "online" event resumes a failed initial read; every save re-reads the cloud row, re-merges current local data and writes with compare-and-swap on user_data.updated_at (conflict → re-read), and the same sync refreshes active accounts on focus/visible/online/60s; sign-out archives the owner's local copy and shows a separate guest copy; load never wipes or re-seeds stored lists (empty arrays are valid). Why: no overwrites across devices, no cross-account leaks, no lost offline edits.
- Phone store + bridge base are owned per account (alignMobileOwner archives/restores them; syncs refuse when owners differ); while the phone design runs, the bridge base only advances for values the phone already holds. Why: stops cross-account copying and stale-phone reverts.
- Calendar day keys use local time (localISO in src/lib/utils.ts; evoLocalKey in the phone prototype), never toISOString(). Why: UTC keys shift days for users outside UTC.
- Bridge and cloud rules are covered by src/lib/mobile-bridge.test.ts and src/lib/evolution-data.test.ts (bunx vitest run). Why: sync regressions are silent data loss.
- Bank data lives only in public.bank_* tables (owner-only SELECT via is_finance_owner() + owner_id; writes only server-side with the service role; tokens AES-GCM encrypted in bank_connection_secrets, no client grants) and in the in-memory bankStore (src/lib/finance-store.ts); never in evolution-data, localStorage or the mobile bridge. Why: private financial data must not leak across accounts or devices.
- Finance math is pure in src/lib/finance-core.ts: totals use the latest retrieved snapshot per active account (superseded/needs_review/sandbox excluded), flows only with complete coverage, refunds only with explicit evidence, unclassified inflows unknown; covered by src/lib/finance.test.ts. Why: avoids double counting and fake figures.
- Counted totals have one source: workouts via workoutCount/fitnessWeek (new page/quick-log sessions are workouts entries with src:"log" and add on top; untagged legacy entries vs legacy aggregate rows stay max-per-day, never summed or deleted), guitar via guitarFocusOnly (only explicitly linked gm-<id> mirrors excluded; unlinked focus records never guessed), trading P/L via the tradingTxns ledger (a review's P/L only changes the ledger when its field is explicitly edited — applyReviewPnl; ledger deletes refresh stored review P/L), journal via journalEntries (legacy journal read-only). Why: prevents double counting and ghost totals after deletes.
- Phone-only sections are kept per account in EvolutionData.phoneStore (raw, versioned; tasks/events and tasks-screen UI state excluded) and reconciled by mobile-bridge with a three-way merge against a per-owner phone base (evolution:mobile-bridge:phone-base:v1, advanced only where the running phone holds the merged value); the resolved snapshot is always written before the frame starts; cloud sync merges phoneStore per domain/record via src/lib/record-merge.ts (id collisions keep both; bridge records each rename in a per-owner alias map, evolution:mobile-bridge:id-alias:v1, applied to the running phone's copy and cleared once the phone is rewritten, so identity stays stable); unowned legacy phone stores are backed up (:unowned), adopted only by a guest device. Why: no lost restores, stale-phone reverts or cross-owner assignment, without claiming desktop parity.

- Phone manual investing balances come from public/evolution-mobile/inv-ledger.js: balance = account `open` + Σ P/L of trades linked by stable acctId; legacy accounts get deterministic ids and open = stored bal − linked P/L (openSrc "derived-v1", raw legacyBal kept). Why: add/edit/delete stay reversible and account removal can't re-point other trades.
